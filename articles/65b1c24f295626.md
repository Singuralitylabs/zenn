## 概要

本記事は、[チーム開発記録32：ver5リリースと脆弱性対応](https://zenn.dev/singularitylabs/articles/24fa3e3a38b774)に続く最新の活動記録です。

シンギュラリティ・ラボのチーム開発では、コミュニティ向けポータルサイトの開発を進めています。前回のver5リリースを経て、今回からプロジェクトは**ver6の開発**に本格移行しました。年内最後となる今回の定例では、**プロフィール画面にSNSアカウントの編集機能を追加する実装**が完了し、プルリクエストのレビュー待ちまで進んだことが報告されました。

会議では、サイドバー見直しタスクのスコープ調整をきっかけに「イシューをどう書けば伝わるか」という運用の議論が白熱し、イシューテンプレートの「概要」欄を**「背景」と「更新箇所」に分割**することが決定。さらに、依存パッケージの更新を自動化する**Dependabot**の導入や、**Claude Code**を軸にAI駆動開発をチームに取り入れていく方針も共有されました。

## 開発したもの

### プロフィール画面へのSNSアカウント入力欄の追加

担当メンバーから、プロフィール画面に自分の各種SNS（X、Facebook、Instagram、GitHub、ポートフォリオサイト）のURLを入力できる欄を作り、入力内容をSupabaseに保存して、会員一覧のモーダルにリンクとして表示されるところまで実装できたと報告がありました。会議時点ではプルリクエストを提出してレビュー待ちの状態です（その後マージ済み）。

入力欄には、URLとして不正な値が保存されないよう、送信前のバリデーションが組み込まれています。

```tsx
// app/(authenticated)/profile/components/Template.tsx（抜粋）
// URL形式チェック関数
const validateUrl = (url: string | null) => {
  if (!url) return true;
  return /^https?:\/\//.test(url);
};
```

各入力欄はMantineの `TextInput` で実装されており、バリデーションエラーがあれば `error` プロパティ経由でその場にメッセージが表示されます。

```tsx
// app/(authenticated)/profile/components/Template.tsx（抜粋）
<div>
  <label htmlFor="x_url" className="block text-sm font-medium mb-1">
    X URL
  </label>
  <TextInput
    id="x_url"
    placeholder="https://x.com/..."
    value={x_url}
    onChange={e => setXUrl(e.target.value)}
    error={errors.x_url}
  />
</div>
```

保存されたURLは、会員一覧の詳細モーダルで「登録があるものだけ」リンクとして表示されます。

```tsx
// app/(authenticated)/members/components/MemberDetailModal.tsx（抜粋）
const hasLinks =
  memberInfo.x_url ||
  memberInfo.facebook_url ||
  memberInfo.instagram_url ||
  memberInfo.github_url ||
  memberInfo.portfolio_url;
```

```tsx
// app/(authenticated)/members/components/MemberDetailModal.tsx（抜粋）
{memberInfo.x_url && (
  <Anchor
    href={memberInfo.x_url || ""}
    target="_blank"
    rel="noopener noreferrer"
    underline="hover"
  >
    X URL
  </Anchor>
)}
```

### イシューテンプレートの見直し — 「概要」を「背景」と「更新箇所」に分割

会議での議論（詳細は後述）を受けて、GitHubのイシューテンプレートを改訂しました。これまで1つの「概要」欄にまとめて書いていた内容を、**なぜ変えたいのか（背景）**と**どこを変えるのか（更新箇所）**に分けています。担当メンバーが会議直後に対応し、こちらもマージされています。

```markdown
<!-- .github/ISSUE_TEMPLATE/feature_request.md（変更後・抜粋） -->
## 背景

<!-- 追加・改善したい理由を簡潔に記載してください -->

## 更新箇所

<!-- 追加・改善したい変更機能について簡潔に説明してください -->
```

機能要望だけでなく、バグ報告は「障害内容」と「対応内容」、リファクタリングは「問題点」と「改善方法」というように、テンプレートの種類ごとに理由と対応を分ける形で統一しました。

### 進行中のタスク

## 会議の様子

### サイドバー見直しのスコープを絞る — 「別イシューに切り出す」文化

サイドバーの構成見直しタスクについて、担当メンバーから「名称変更や並び替えだけでなく、資料や動画といった各コンテンツの中身の分類まで手を付けると、かなり大掛かりになる。どこまでやるか相談したい」という問題提起がありました。

これに対してリードメンバーは、「このタスクで想定しているのは、サイドバーの項目の順番と表題の文言を直すことだけ。コンテンツの中身の分類は対象外」とスコープを明確化。作業中に「こうした方がいいのでは」と感じたことは、**別のイシューとして起票し、ミーティングでやるかどうかをすり合わせてから着手する**という基本の流れも改めて確認されました。思いついた改善をその場で盛り込まず、一度言語化してチームの合意を取る——スコープの膨張を防ぐ、チーム開発らしい進め方です。

あわせて、ver6に向けて「説明欄のマークダウン対応」「サムネイル画像をアプリからアップロードできる機能」「動画の並び順を画面から設定する機能」なども新たにイシュー化されました。

### イシューは誰のために書くのか — テンプレート論争

イシュー起票の話題から、テンプレートそのものの議論に発展しました。あるメンバーからの「今の『概要』欄は書きにくい。長文になるか、悩んで何も書かないかのどちらかになりそう。**『背景』と『修正箇所』に分けた方が書きやすいのでは**」という提案が発端です。

一方でこのメンバーからは「枠が多いと埋めるのが面倒で、イシューを作る気がなくなる」という率直な懸念も。これに対してリードメンバーは「そこはシンプルに埋めてほしい」と返しつつ、**「同期の会議で口頭ベースで伝えるのではなく、なぜ変えたいのかをある程度言語化してからイシューにした方が、コミュニケーションを取りやすい」**という考えを示しました。

提案したメンバーも「背景と変更箇所に分かれていれば、目的と実装内容が合っているかを言語化しやすい」と納得し、最終的に**「背景」と「更新箇所」の2欄に分ける**ことで合意。「一言でもいいので書く」という運用ラインも添えられました。書き手の負担と読み手の理解しやすさ、双方の視点がぶつかったからこそ落としどころが見つかった議論でした。

### Dependabot導入と `package.json` の学び

依存しているフレームワークやパッケージの更新プルリクエストを自動で作ってくれるGitHubの機能、**Dependabot**の導入が提案されました。先日Next.jsの脆弱性対応があったことを踏まえ、「余裕があれば入れてみては」という流れでのタスク化です。

リードメンバーからは「承認なしで勝手にマージされると怖い」という確認があり、承認は必須であることを確認した上で、**「まず1回入れてみて運用を考える」**方針に。提案したメンバーからは「仕事でも一般的に使われているが、プルリクが作られても誰も拾わず溜まっていくパターンもある」という現場のリアルな注意点も共有されました。

この話題をきっかけに、新しいメンバーから「`package.json` に書かれているのは今使っているパッケージなのか」「これだけの数をどうやって選んだのか」という質問が出て、**依存関係とは何か、パッケージはどう選定されるのか**という基礎解説が行われました。「Reactを使えば定番のものが自然と入る」「動画閲覧機能でYouTubeを使うから、そのためのパッケージを入れる、という具合に必要に応じて追加していく」「最初から全部理解しようとせず、使うときに1つずつ理解すればよい」というアドバイスは、これからチーム開発に参加する人にも参考になりそうです。

### AI駆動開発をチームの標準に — Claude Codeと開発環境整備

最後に、リードメンバーから**AI駆動開発をチーム開発にもっと取り入れていく**方針が示されました。具体的には、**Claude Code**を軸に、チーム開発用の開発ルールを記したファイル（`CLAUDE.md` など）を作って管理し、誰でも同じような形で開発できる共通環境を整えていく構想です。

費用面の質問には「月額20ドルのサブスクリプションプラン。アカウントの共用はルール的にNGで、トークンもすぐ消費してしまう」との回答があり、**全員に有料契約を求めるのではなく、実際の開発の様子を見るだけでも得るものがある**というスタンスが共有されました。リードメンバー自身は現在、ターミナルから指示を出す**Claude Code**、エディタ拡張でバグチェックなどを行う**GitHub Copilot**、AI機能標準搭載のエディタ**Cursor**の3つを使い分けているそうです。

参加メンバーからは「GitHub Copilotを契約したら1ヶ月の無料枠があった」という報告もあり、来年からはWeb技術勉強会の時間枠もAI寄りの内容にシフトしていく予定です。なお、年内の定例は今回が最後で、次回は年明け1月8日の開催となります。

## 活用した技術

### Mantineのフォームとクライアントサイドバリデーション

今回のSNS入力欄は、UIライブラリ**Mantine**の `TextInput` コンポーネントで実装されています。Mantineには `error` プロパティが用意されており、文字列を渡すだけで入力欄の下に赤いエラーメッセージを表示できます。

実装では、送信ボタンが押されたタイミングで各URLを正規表現 `/^https?:\/\//` でチェックし、`http://` または `https://` で始まらない値があればエラーを表示して送信を中断します。サーバーに問い合わせる前にブラウザ側で入力ミスを弾く**クライアントサイドバリデーション**は、ユーザーへのフィードバックが速く、不正なデータの保存も防げる基本パターンです。あわせて、外部リンクを新しいタブで開く際の `rel="noopener noreferrer"` 指定など、セキュリティ面の定石も押さえた実装になっています。

### Dependabotと依存関係の管理

**Dependabot**は、GitHubが提供する依存関係の自動更新機能です。リポジトリ内の `package.json` などを監視し、依存パッケージに新しいバージョンや脆弱性修正が出ると、更新用のプルリクエストを自動で作成してくれます。

現代のWebアプリは、自前のコードだけでなく多数の外部パッケージの上に成り立っており、あるパッケージの更新が別のパッケージに影響することも珍しくありません。手動での追従には限界があるため、こうした自動化ツールが広く使われています。一方で、自動作成されたプルリクを放置すれば溜まっていく一方なので、「誰がいつ確認してマージするか」という**運用ルールとセットで導入する**ことが重要です。今回のチームの「まず入れてみて運用を考える」「マージには必ず承認を挟む」という進め方は、小さく始める導入の好例といえます。

### AI駆動開発ツールの使い分け — Claude Code・GitHub Copilot・Cursor

AI駆動開発と一口に言っても、ツールごとに得意分野が異なります。**Claude Code**はターミナル上で動くエージェント型のツールで、自然言語の指示からコードの作成や修正まで自律的に進められます。**GitHub Copilot**はエディタの拡張機能として動作し、コード補完やバグチェック、プルリクエストのレビューが得意です。**Cursor**はAI機能を標準搭載したエディタで、コードについての質問や編集をシームレスに行えます。

チームでAI駆動開発を進める上で鍵になるのが、`CLAUDE.md` のような**開発ルールファイルの共有**です。プロジェクトの構成や命名規則、レビュー基準などをファイルとして管理しておけば、誰がAIに指示を出しても同じ前提で開発を進められます。個人の生産性向上にとどまらず、チームの開発標準をAIに引き継ぐ仕組みとして注目されているアプローチです。

## 総括

年内最後の定例となった今回は、ver6の最初の目玉となるSNSアカウント表示機能がレビュー段階まで進み、会員同士のつながりを深める機能が形になってきました。会員一覧の役割別表示やカレンダー表示など、ユーザーに見える改善も複数並行して進んでいます。

また、イシューテンプレートの見直しでは「書き手の負担」と「読み手の理解」のバランスをめぐる本音の議論が交わされ、Dependabotの導入検討では現場経験に基づく運用の注意点が共有されるなど、コードの外側にあるチーム開発の質を高める話題が多い回でもありました。来年に向けて打ち出されたAI駆動開発の方針も含め、ver6の開発とともにチームの開発スタイル自体が進化していきそうです。

シンギュラリティ・ラボのチーム開発では、こうした実践的な開発経験を通じてスキルアップしたい仲間を募集しています。興味のある方はぜひご参加ください。

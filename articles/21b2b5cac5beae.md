## 開発したもの

### セキュリティリスク対応：API ルートの認証必須化

未認証ユーザーが叩ける API ルートをセキュリティリスクとして特定し、認証を必須にする対応が完了しました（PR #432）。

カレンダーイベント取得エンドポイントでは、認証ユーザーを必須にする実装パターンが取られました：

```typescript
import { USER_STATUS } from "@/app/constants/user";
import { requireApiUser } from "@/app/services/auth/require-api-user";

export async function GET() {
  const auth = await requireApiUser([USER_STATUS.ACTIVE]);
  if (!auth.ok) {
    return auth.response;
  }

  // 以下、認証済みユーザーの処理
}
```

また Slack 通知エンドポイントでも、ペンディング（登録待ち）ユーザーを認証対象にし、不正アクセスを防止する実装が施されました。

## 会議の様子

### Issue カンバンボード運用ルールの明確化

チーム内での Issue ステータスの定義がこれまで曖昧だったため、今回の定例で運用ルールを統一しました。

**最終的な運用ポリシー（決定事項）:**

- **インプログレス（In Progress）**: 設計・実装・レビュー中のすべての段階に適用。プルリクエスト作成からマージまでの間、常にこのステータスに置く
- **チェック（Check）**: マージが完了したものの、定例で確認がまだ済んでいないもの。レビュー完了後、チーム内で共有・確認する最終段階
- **レディー・サーベイ（Ready for Survey）**: 要件確認が必要なもの

このルール化により、Issue カードの行き来が減り、チーム全体での進捗把握が容易になります。

### シンラボ動画ライブラリへのカレンダー機能検討

シンラボが配信した動画を日時ベースで検索・閲覧しやすくするための機能追加を検討しました。複数のアプローチが議論されました：

1. Google カレンダーの「リスト表示」モード活用
2. 動画一覧ページにフィルター・ソート機能を追加
3. テーブル形式での表示への切り替え機能

結論として、カレンダー機能は調査段階にとどめ、まずはテーブル表示への切り替え機能を優先実装することになりました。フィルター機能もテーブル実装後に追加される予定です。

### Supabase アクセストークン環境設定トラブル

チームメンバーの開発環境で、Supabase CLI 実行時にアクセストークンが取得できないエラーが発生しました。権限変更（Developer → Maintainer）での検証や、リポジトリの再クローンなど、複数のアプローチを試しながら原因特定を進めました。

最終的には、30 日有効期限のアクセストークンを新規発行して対応することになりましたが、根本原因の特定は継続調査となっています。

## 活用した技術

### Next.js API ルートのセキュリティパターン

`requireApiUser` というユーティリティ関数を活用し、API ルート毎の認証チェックを統一化。USER_STATUS による段階的な認証管理により、活動中ユーザー・登録待ちユーザーなど、異なるステータスに対応した柔軟な認可が可能になります。

### GitHub Issue 運用の構造化

Zenn をはじめとしたプロジェクト管理ツールでよく見られる「ステータス」の概念を、チーム内で明示的に定義することで、誰もが同じ理解で Issue を扱えるようになります。特に「インプログレス」の定義をプルリクエスト全体の期間に拡大したことで、設計・実装・レビューという複数フェーズが一つのステータスで透視的になり、進捗の曖昧性が減少します。

### Supabase CLI と認証環境

開発環境での Supabase CLI 操作には、アクセストークンが必要となります。このトークンは個人単位で発行・管理する必要があり、30 日の有効期限管理が運用課題となり得ます。

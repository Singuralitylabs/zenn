## 開発したもの

### 動画一覧ページの実装（PR #66）

Supabase から動画データを取得して表示する動画一覧ページを実装しました。`VideosPageTemplate` コンポーネントと `VideoCard` コンポーネントを新規作成し、ページタイトルを共通コンポーネント `PageTitle` として切り出しました。

```typescript
// app/services/api/videos.ts
import { createServerSupabaseClient } from "./supabase";

export async function fetchVideos() {
  const supabase = await createServerSupabaseClient();
  const { data, error } = await supabase
    .from("videos")
    .select("*")
    .eq("is_deleted", false);

  if (error) {
    console.error("Supabase 動画一覧データ取得エラー:", error.message);
    return { data: null, error };
  }

  return { data, error: null };
}
```

### データベース設計書へのRLSポリシー追加（PR #87）

Supabase の RLS ポリシーをデータベース設計書に整理・追加しました。users テーブルに対して閲覧・挿入・更新・削除の各ポリシーを定義しています。

```sql
-- admins_can_read_all_users: 管理者は全ユーザーデータを閲覧可能
EXISTS (
    SELECT 1 FROM users
    WHERE
    clerk_id = get_clerk_user_id()
    AND role = 'admin'
    AND is_deleted = FALSE
)

-- admins_can_update_all_users: 管理者はすべてのユーザー情報を更新可能
EXISTS (
    SELECT 1 FROM users
    WHERE
    clerk_id = get_clerk_user_id()
    AND role = 'admin'
    AND is_deleted = FALSE
)
```

## 会議の様子

### ユーザー承認機能の設計議論

メンバーが参加申請した際に管理者が承認・拒否できる機能の仕様について議論しました。ユーザーのステータスは `pending`（承認待ち）・`active`（承認済み）・`rejected`（拒否）の3種類とし、Clerk Webhook でユーザー作成時に `pending` に設定する設計にすることが決まりました。

承認・拒否の処理については `update_user` のような関数を1つ用意し、引数でステータスを渡す方式が採用されました。

### RLSポリシーの設計レビュー

既存の RLS ポリシーに対していくつかの問題点が指摘されました。

**`is_registered_user` 関数の整理**：管理者向けポリシーに含まれていた `clerk_id = get_clerk_user_id()` の条件が、管理者が他のユーザーを操作できなくする不具合につながるとの指摘がありました。管理者ポリシーからはこの条件を外す対応が必要との判断になりました。

**`is_deleted` の重複チェック**：`is_registered_user` 関数と RLS ポリシーの両方で `is_deleted` を確認しており、二重チェックになっていることが発覚。設計書へのコメントと修正対応が依頼されました。

**削除ポリシーの方針**：論理削除（`is_deleted = TRUE` に更新）を前提としているため、物理削除は管理者のみ Supabase 管理画面から直接実施する方針となりました。削除ポリシーは基本的に許可しない方向で設計を見直すことが決まりました。

### 承認待ち・拒否時の画面設計

承認待ちユーザーがアクセスした際のルーティングについて、以下の方針を確認しました。

- 承認待ち状態：承認待ち画面へリダイレクトし、ログアウトボタンを表示
- 拒否状態：ログイン画面（トップページ）へリダイレクト

承認待ち画面は Bolt.new などの AI ツールを使って UI を生成する案も出ました。

### AIツール（Devin）の活用検討

チームリーダーから、AI 開発エージェント「Devin」を試験的に導入したいという提案がありました。指示を与えるだけでアプリをほぼ自動で構築してくれるとのことで、まずはポータルサイト本体とは独立した小さなプロダクト（ゲームなど）で試してみる方針となりました。

### 動画詳細ページの進捗

動画詳細ページはビルドエラーの修正が完了し、残りはレスポンシブ対応のみとの報告がありました。当日中の対応が予定されています。

## 活用した技術

### Supabase Row Level Security（RLS）

Supabase の RLS はテーブル単位でアクセス制御ルールを定義する機能です。今回は `users` テーブルに対して SELECT / INSERT / UPDATE の各操作について、一般ユーザーと管理者ロールに分けたポリシーを設計しました。

`get_clerk_user_id()` はカスタム関数で、現在ログイン中のユーザーの Clerk ID を取得します。この関数を活用することで、JWT から取得したユーザー情報を SQL ポリシー内で参照できます。

### Supabase PostgreSQL Functions

ユーザー承認・拒否処理のために、ステータスを引数で受け取って更新する関数（`update_user` 相当）の作成が決定しました。Supabase の Functions 画面から管理でき、RLS ポリシー内でも利用できます。

### Next.js App Router + Mantine UI

動画一覧ページは Next.js の App Router 構成で実装しました。Server Component として `fetchVideos()` でデータを取得し、Client Component の `VideosPageTemplate` に props として渡す構成です。UI には Mantine の `Card`・`Grid`・`Text` コンポーネントを活用しています。

また、ページタイトルを `PageTitle` コンポーネントとして共通化することで、資料一覧・動画一覧のスタイルを統一しました。

```typescript
// app/components/PageTitle.tsx
'use client';

import { Title } from '@mantine/core';
import { ReactNode } from 'react';

export function PageTitle({ children }: { children: ReactNode }) {
  return (
    <Title order={1} p="1.25rem 0" style={{ borderBottom: '1px solid #888' }}>
      {children}
    </Title>
  );
}
```
